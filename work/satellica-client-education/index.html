Case study · Client education & AI-assisted operations

Teaching clients to self-serve across a 12-hour time gap

At Satellica, an AI-powered UX research platform, clients in North America and China kept getting stuck on the same setup questions while the team was asleep. I designed a task-based help center of six guides so researchers and PMs could launch studies on their own, and built a human-in-the-loop Claude workflow that took the repetitive recruitment operations off my plate.

01 · The problem

The same five questions, arriving overnight

Satellica's clients were product teams at hardware and consumer-tech brands. They signed up to run AI-moderated interviews, AI surveys and human-led studies on a platform that was new and changing fast, where features like AI moderation and two-stage screening had no familiar equivalent.

Questions came in by WeChat and Lark, two or three a day, often while our team was offline. A client who got stuck on screener logic at 10 a.m. in Shenzhen waited until evening for an answer, and their study launch slipped by a day.

When I sorted the questions I was answering, five categories covered almost all of them. That told me the problem was not product complexity in general. It was a small number of specific tasks that clients didn't have a reference for.

02 · Design approach

Organize by the job, not by the menu

Product docs often walk through the interface screen by screen. Clients don't think that way. They arrive with one job, like "launch my first AI interview," and need the shortest path to it. So every guide is built around one task, in the order the client will actually do it.

Task-based structure

One guide, one job

Each guide follows the build sequence Plan → Recruit → Launch, so the headings double as a checklist. Clients can jump to the step they're stuck on.

Microlearning video

Short clips per step

Instead of one long walkthrough recording, I recorded a short screen video for each step, kept in Canva and shared with clients alongside the written guides. Clients replay only the part they need, and a single clip can be re-recorded when the UI changes.

Decision support

Answer "which one?" up front

Guides open with a "Which study type should I pick?" box and end with comparison tables, because choosing the wrong path was a common source of rework.

Expert judgment, written down

Best-practice tips

Amber tips carry the research craft the UI can't teach: end each prompt with a question, offer 3–5× the time slots you need, split screener questions across pages so candidates can't guess the target.

Error prevention

Notes on what breaks

Blue notes flag the constraints that cause support tickets, like Web and Mobile sections being mutually exclusive, or Carry Forward and Display Logic not sharing a question.

Versioned content

Built to be maintained

Every guide shows a version number, update date and read time. The core guides are on V2.0, updated in July 2026 as the product changed.

Anatomy of a guide

  1. Header with category, version, update date and read time (6–9 min).
  2. Decision box that routes the reader to the right study type before they start.
  3. Numbered steps matching the product's own Plan → Recruit → Launch tabs.
  4. Annotated figures with highlighted UI and a one-line caption each.
  5. Tips and notes in two consistent styles, so readers learn what each color means.
  6. Keep exploring links to the next guide in the client's journey.
Best-practice tipOffer 3–5× the slots you need. Opening 5 slots for 5 participants under-fills, since many candidates pick the same time.
NoteGenerate with AI, Upload existing and Start from scratch are mutually exclusive. Switching paths clears what you entered.

04 · AI ops workflow

A Claude playbook with a human at every gate

The guides handled client questions. My own time was going to recruitment operations: copying screener answers between User Interviews and Satellica, messaging qualified applicants one by one, sending NDAs, chasing reminders. For a study with hundreds of applicants, that was days of clicking.

I wrote the work up as a prompt playbook that Claude runs in the browser. Each prompt is a written procedure with the project links and message copy filled in. Claude prepares each action and I review it before it goes out. Nothing is sent to a participant without my approval.

Stage 1 · Initialize

Build the tracker

Pull screener questions from User Interviews and second-round survey questions from Satellica into one recruitment table as columns.

User Interviews → Satellica → SheetI check the columns
Stage 2 · Contact

Send second-round screener

For each applicant marked Qualified, check the message history. Skip anyone already asked; message the rest with the survey link and a 24-hour deadline.

User Interviews inboxI approve each send
Stage 3 · Sync

Merge both screeners

Copy completed Satellica sessions into the tracker, then match User Interviews screener data by first and last name. Skip image data.

Satellica → Sheet ← User InterviewsI spot-check matches
Stage 4 · Consent

Send the NDA

Prepare a named copy of the NDA in Drive, place signature fields, request e-signature, then message each scheduled participant to sign before the session.

Google Drive eSignatureI review before sending
Reminder rule

For the smart-guitar study, this rule got 30 AI interviews completed before the client's deadline without anyone being messaged twice in a day.

Excerpt · Stage 2 prompt 
# Send second-round screener request
Step 1: Open my Chrome browser
Step 2: Go to User Interviews → open [project · Applied tab]
For each participant marked QUALIFIED:
  • Open their profile → Message tab
  • Check if we already asked them to
    complete the premium screening survey
  • If yes, skip it.
  • If no, send this message in an
    easy-to-read structure:

  "Hi, thanks for your interest in our
   study! Before we can book you in, we'll
   need you to fill out an additional form
   to determine your final eligibility.
   Please complete it within 24 hours:
   [second-round survey link]"

Bracketed fields are swapped per study, so the same playbook runs every project.

06 · Reflection

What I'd build next

A guide-grounded support bot

I proposed an AI chatbot trained on the help center to answer client questions in either time zone. It's pending budget. The guides were written to be that bot's source material.

Measure, don't estimate

My impact numbers come from my own tracking. Next time I'd set up help-center page analytics and tag support messages by category from day one.

Share the playbook

The Claude workflow stayed with me. Packaged with the checklist and a short training session, teammates could run it too.
